# Status LEDs

Five 0805 SMD indicators in a row along the south edge (D6, D7, D10, D11,
D12), each with a silk caption so the cluster is self-documenting. All are
direct-driven (the v1 serial-activity LEDs and the blue MOSFET-driven user
LEDs are gone — see the v2 cost-down in `ROADMAP.md`).

| LED | Silk | Color  | Driven from        | Series R | Means |
|-----|------|--------|--------------------|----------|-------|
| D6  | `5V` | red    | +5V rail           | R15      | USB/5V power present |
| D7  | `3V3`| red    | +3.3V rail         | R16      | LDO regulated rail up |
| D10 | `TX` | red    | IR_TX (GPIO5)      | R19      | IR transmit activity |
| D11 | `USR1`| yellow | USER_LED1 (GPIO3) | R25      | user-programmable |
| D12 | `USR2`| yellow | USER_LED2 (GPIO4) | R20      | user-programmable |

Cathodes go to GND; anodes are fed through the series resistor from the rail
(D6/D7) or the GPIO (D10/D11/D12). The two user LEDs are yellow (low Vf) so
they run directly off a 3.3V GPIO with no FET — the v1 blue LEDs needed the
5V rail + 2N7002, both deleted.

## Brightness / resistor values

Power and activity indicators only need to be *seen*, not bright. Confirm the
fitted series values in `hardware/BOM.md` against the rail/GPIO voltage and
the LED Vf when tuning; bump toward a larger resistor if any LED looks glaring
next to the others.

## Silk captions

The per-LED captions (`5V`, `3V3`, `TX`, `USR1`, `USR2`) are generated by
`scripts/pcb_silk.py` (`STATUS_FN`), anchored below each footprint so they
track a re-layout. Update that map, not the board by hand, if an LED's
function changes.
