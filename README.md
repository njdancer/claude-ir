# claude-ir — ESP32 IR smart controller for ActronAir AC

A smart IR controller for an **ActronAir** (rebranded Midea) air conditioner.
The remote's IR protocol has been fully reverse-engineered, and a working
ESP8266 breadboard transmits real commands to the AC. The active mission is a
custom **ESP32-C3** dev board, taken from schematic → PCB → fabricated,
verified unit → production firmware → eventual HomeKit.

> 🤖 **Designed end-to-end by [Claude](https://claude.ai)** (Anthropic),
> directed by Nick Dancer. Reverse engineering, schematic, PCB layout,
> firmware, and the web UI were produced autonomously. Non-commercial hobby
> project.

📦 **Published board artifacts** (regenerated on every merge):
**<https://njdancer.github.io/claude-ir/>** — interactive 3D board viewer,
schematic PDF/SVGs, BOM, and the JLCPCB fabrication package.

## The ESP32-C3 board (`hardware/`)

The custom board uses an **ESP32-C3-WROOM-02** module whose native
USB-Serial-JTAG controller means no USB-UART bridge chip: flash and monitor run
straight over USB-C. Key subsystems: 4× IR-emitter array (TSAL6200 via an
AO3400A driver), TSOP38238 IR receiver, AHT20 I²C temp/humidity sensor,
AMS1117-3.3 LDO from USB-C 5 V, and status/user LEDs. GPIO map and
per-subsystem rationale live in [`hardware/notes/README.md`](./hardware/notes/README.md).

**CI is the authoritative hardware gate** (`.github/workflows/ci.yml`): every PR
runs ERC/DRC vs `hardware/ci-baseline.json`, netlist freshness, schematic↔PCB
parity, page-extent and 3D-model checks, BOM LCSC lint, firmware builds + native
tests, and the app's typecheck/unit/e2e. Open a PR and watch CI rather than
re-running the battery by hand.

```bash
./scripts/hardware-check.sh              # ERC + regenerate netlist (needs kicad-cli)
python3 scripts/ci/hardware_validate.py  # full design gate (what CI runs)
python3 scripts/fab-outputs.py           # regenerate the JLCPCB order package
./scripts/build-site.sh                  # build the Pages site (schematic, 3D viewer, fab)
```

> ⚠️ KiCad work happens on Nick's Mac (KiCad 9 + the kicad MCP). Remote/web
> sessions do firmware, analysis, app, docs, and planning only — they queue
> KiCad tasks in `ROADMAP.md`.

## IR protocol

ActronAir is controlled with two protocols, both natively supported by
IRremoteESP8266:

- **BOSCH144** (144-bit) — climate state: power-on, temperature, mode, fan.
- **COOLIX** (24-bit) — discrete commands: power-off (`0xB27BE0`), swing, boost, LED.

The two payloads carry **disjoint** attributes, so AC state can be partially
stale after any single command — firmware must track per-payload freshness.
Full byte maps and timings are in [`re-findings.md`](./re-findings.md).

## Breadboard reference (working POC)

The proven ESP8266 reference that the board is based on:

- **Board:** ESP8266 NodeMCU (ESP-12E)
- **IR RX:** TSOP/VS1838B-class receiver OUT → GPIO14 (D5)
- **IR TX:** IR LED (940 nm) driven by a 2N2222 on GPIO4 (D2), 470 Ω base / current-limited LED

Full wiring is in [`wiring.md`](./wiring.md). The firmware exposes a 115200-baud
serial command interface:

| Command | Example | Description |
|---------|---------|-------------|
| `POWER:ON` / `POWER:OFF` | `POWER:ON` | On (BOSCH144) / Off (COOLIX) |
| `TEMP:<16.0–30.0>` | `TEMP:22.5` | Set temperature (0.5° steps) |
| `MODE:<COOL\|HEAT\|DRY\|FAN\|AUTO>` | `MODE:COOL` | Set mode |
| `FAN:<AUTO\|20…100>` | `FAN:60` | Set fan speed |
| `SWING` / `BOOST` / `LED` | `BOOST` | Special functions (COOLIX) |
| `STATE` | `STATE` | Query tracked state |

Responses are `OK:<message>` or `ERROR:<message>`.

## Web control UI (`app/`)

A React Router (v7) full-stack app for AC control over serial, with a mock
serial mode for hardware-free development.

```bash
cd app && pnpm install
MOCK_SERIAL=true pnpm dev   # http://localhost:5173, no hardware needed
pnpm test                   # vitest unit tests
pnpm test:e2e               # playwright e2e
```

For real hardware, set the serial port in `app/app/lib/serial.server.ts`.

## Build & test

```bash
pio run -e esp32-c3              # build the ESP32-C3 board firmware
pio run -e nodemcuv2             # build the ESP8266 breadboard firmware
pio test -e native              # host-side unit tests
./scripts/flash.sh              # flash from the macOS host
./scripts/monitor.sh            # serial monitor (115200)
python3 scripts/capture.py <lbl># capture one IR signal to captures/
python3 analysis/decoder.py     # analyze the capture corpus
```

Firmware builds run in the podman devcontainer (or host); flash/monitor run on
the macOS host (USB passthrough doesn't work under podman/macOS).
